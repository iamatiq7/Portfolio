# DEPLOYMENT — GitHub Pages

Target: **https://iamatiq7.github.io/Portfolio/** (repository `iamatiq7/Portfolio`)

This is a GitHub Pages **project site**: it is served from the `/Portfolio/` sub-path. That is why the production build must use `npm run build:gh` (which sets `base: '/Portfolio/'`). A default `npm run build` produces root-relative asset URLs and will render an unstyled page on GitHub Pages — this is the single most common failure mode.

---

## Option A — Deploy with GitHub Actions (recommended)

1. Push the project source to the repository (the `Portfolio-v2` folder becomes the repo root — or move its contents to the root of `iamatiq7/Portfolio`).
2. In the repository, create `.github/workflows/deploy.yml`:

```yaml
name: Deploy portfolio to GitHub Pages

on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: true

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: npm
      - run: npm ci
      - run: npm run build:gh
      - uses: actions/upload-pages-artifact@v3
        with:
          path: dist
  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - id: deployment
        uses: actions/deploy-pages@v4
```

3. Repository → **Settings → Pages → Build and deployment → Source: GitHub Actions**.
4. Push to `main`. The workflow builds and publishes automatically.
5. Open https://iamatiq7.github.io/Portfolio/ and hard-refresh (Ctrl+F5) after the first deploy.

> If `npm ci` complains about a missing lockfile, commit `package-lock.json` (it is generated by `npm install`) or switch the step to `npm install`.

## Option B — Manual deploy from your machine

```bash
cd Portfolio-v2
npm install
npm run build:gh

# publish only the build output to the gh-pages branch
npx gh-pages -d dist --repo https://github.com/iamatiq7/Portfolio.git
```

Then: **Settings → Pages → Source: Deploy from a branch → Branch: `gh-pages` / root**.

If you prefer to keep source and build in the same branch, use the `docs/` folder workflow instead: build into `docs/`, commit, and set Pages source to `main /docs`.

## Rollback

Every deploy is a commit or an artifact — reverting is cheap:

**Actions route**
1. `git revert <bad-commit>` on `main` (or open the workflow run → "Re-run" a previous successful run).
2. Push. The previous build is republished within ~1 minute.

**gh-pages branch route**
```bash
git checkout gh-pages
git log --oneline -5           # find the last good commit
git reset --hard <good-sha>
git push --force origin gh-pages
```

**Emergency**: Settings → Pages → set Source to "None" to take the site offline instantly (keeps the repository intact).

## Common problems

| Symptom | Cause | Fix |
|---|---|---|
| Page is unstyled, assets 404 under `/assets/…` | Built with `npm run build` instead of `build:gh` | Rebuild with `npm run build:gh` |
| Assets 404 under `/Portfolio/Portfolio/…` | `base` set twice (e.g. base + absolute URLs in data) | Keep asset paths in `portfolio.js` relative (`assets/…`, no leading slash) |
| Fonts fall back to system sans | `public/assets/fonts/*.woff2` not committed | Commit the fonts folder |
| Blank page after deploy | JS bundle 404 or a build error | Check Actions log; run `npm run build:gh` locally and confirm `dist/assets/*.js` exists |
| Old content still visible | Browser/CDN cache | Hard refresh; GitHub Pages caches ~10 min |
| Images missing but layout intact | File absent → `SmartImage` placeholder | Add the file per `asset_guide.md` |

## Custom domain (optional)

1. Add a `CNAME` file in `public/` containing the domain (e.g. `kazi.dev`).
2. Configure the DNS `A`/`CNAME` records per GitHub's instructions.
3. Settings → Pages → Custom domain → enable "Enforce HTTPS".
4. When using a custom domain at the root, switch the build to `npm run build` (base `/`) and update `index.html` canonical/OG URLs.
